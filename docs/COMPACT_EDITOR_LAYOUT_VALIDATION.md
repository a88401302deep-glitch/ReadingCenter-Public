# 緊湊書籍編輯／手機滿寬封面

2026-10-30，基準公開 main26bbde0／私人 main13799d0。使用者實機指出前批仍有欄位過長、出版社高度造成空列、手機封面兩側留白，並詢問不應暴露的封面路徑；前批部署不能視為實機驗收通過。

唯一目標：重新安排書籍編輯表單的欄位密度與手機封面，不改正式資料、API或部署設定。

- 表單改為明確分組；出版資訊：寬版出版社、ISBN、日期同行，ISBN上限14rem、日期11rem；760px直向出版社自行一列、ISBN與日期並排。原文／譯者／繪者寬版4欄、平板2欄；系列／卷次／排序／字數4欄。短欄位不再受出版社控制高度拖出空列。
- 書名／作者單行起始，作者依內容增高。重複的「選填／完整度必備」提示不佔版面，出版書名以必填星號與原生required保留提示；其他欄位保存與必填驗證不變。
- 手機：書名→滿內容寬度封面→作者→短按鈕列；按原圖比例顯示，不裁切，不以固定180px縮成中央小圖。單書頁手機封面同樣去除320px上限與固定比例。未設定封面只顯示短佔位，不預留巨大空框。
- 平板封面左置、書名作者右上，短按鈕及補全查詢在右下；移除巢狀大卡片及多餘段距。原粉色、圓角、44px觸控及固定底部動作保留。
- 移除「封面路徑／封面檔案路徑」UI；BookCover原始path、MIME、尺寸仍由草稿保留及上傳流程管理。選檔改由「上傳封面」按鈕呼叫原選檔器；貼上按鈕支援Ctrl+V，剪貼簿失敗才出現備用貼上欄。原上傳只在儲存發生、失敗不儲存、取消不覆寫機制保留。
- 出版社仍可輸入及選用既有字典；手機上下排列，避免Safari窄版原生選單溢出。沒有新增分類字典、改寫出版社或匯入私人資料。

本機驗證：29項元件測試通過（封面失敗／重試／取消／原封面保存、貼上回退、scope、出版社、書目補全）；32個唯一分層Chromium／WebKit案例通過，涵蓋封面搜尋採用與取消、分類、最近閱讀、出版社、metadata流程、768直向／1024×768橫向／1366平板、320／360／430手機滿寬及無溢出。最終8項排版與12項出版社／metadata案例各自通過；typecheck、範圍lint、build、diff check通過。

診斷紀錄：初始合成上傳圖片無法解碼，改為瀏覽器canvas產生有效PNG，並使用符合JPEG上傳契約的測試回應；不修改正式上傳驗證。其後定位兩個版面問題：舊mobile grid-row優先度讓平板書名／作者無法並排，已修正；WebKit320px額外捲動33px，逐區塊隱藏量測確定來自publication中的過窄出版社原生選單，改手機上下排列後消除。1366寬版ISBN超過300px，已設短欄位上限；沒有降低測試標準或以重試代替診斷。

合成截圖：.local-dev/compact-editor-design/tablet-editor-1024.png、tablet-publication-1024.png、phone-editor-360.png已目視。所有驗證僅使用合成書籍與圖片。

狀態：本機候選，尚未合併或部署；完整CI及私人等效核對另行記錄。驗收先看手機封面是否貼齊內容區且不裁切、平板出版欄位是否變短且同行；實際選圖→儲存／取消與出版資料保存於候選驗證。正式發佈依CONTRIBUTING.md須另外授權。
